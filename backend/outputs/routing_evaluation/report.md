## Scripting policy (offline stand-ins)

- No network access. LLM-judgment calls are scripted per turn from a
  gold-informed agenda: SafetyAgent CRISIS iff the turn's gold family is
  crisis; TherapyDecider opens the gold therapy on the first gold-therapy
  turn; ES opportunity skills offer only the gold-expected skill and only
  when the engine's own pure-code `_gate` fires first.
- Derivation policy: an ES turn counts as routed when the engine's
  `_gate` fired AND the scripted agenda offered the gold-expected skill
  AND the offer landed as a proposing/active sub-state at the turn
  boundary. Gold ES cases are single-turn messages, so the offer (not
  user acceptance) is the product's routing job; a turn with no offer at
  all derives as DAILY. Offer-made-but-not-accepted is still counted as
  EMOTION_SUPPORT — acceptance belongs to the user, noticing is ours.
- Consequence: metrics measure the real routing / priority / state
  machinery (crisis short-circuit, signals, ESO priority and supersede,
  cooldowns, FLOW/pick_skill, therapy stop rules), NOT LLM classification
  accuracy. safety_override_accuracy documents the actual
  short-circuit behavior of the system under this agenda.
